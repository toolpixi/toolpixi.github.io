Do QR Codes Expire?

The pattern never expires. What can stop working is the thing behind it — and whether it does depends on one question: static or dynamic?

The short answer

No — a QR code has no built-in expiry date. A QR code is a pattern of squares that spells out some text, the same way a barcode spells out a number, and ink does not expire. Scan a code printed years ago and the phone reads exactly what was put into it. What can expire is the thing the text points to: the web page it links to, or the redirect service sitting between the code and the page. Whether your code is safe for ten years or dead in a fortnight depends entirely on which kind of code you made — static or dynamic — and most people who think their code "expired" actually made the wrong kind without realising it.

Static vs dynamic: what is actually inside the code

A static QR code stores your content directly in the pattern: a web address, a phone number, Wi-Fi credentials, a contact card, a block of text. A phone reads the pattern and acts on it directly. No server is involved, nobody sits in the middle, and nothing can switch it off — which is why the QR Code Generator on this site makes static codes: your link is encoded in the pattern, generated on your device, and the code works for as long as the thing it points to still exists.

A dynamic QR code stores something else: a short link on the generator's own domain, something like qr.example/x7Gk. When someone scans it, their phone goes to the generator's server, which looks up where that short link should go and forwards the visitor onward. That detour is genuinely useful — you can change the destination after printing, and the provider can count the scans. But the code now works only while that provider keeps redirecting it for you, on whatever terms your account has. The printed pattern is identical either way; the difference is invisible until the day the redirect stops.

Dynamic QR codeA short link on the provider's domainCan stop when a trial ends, a plan lapses, or the provider closesUsually a subscription

Where QR codes really "expire"

Trials and plans. Many generators make dynamic codes by default, and the free tier comes with conditions: trials commonly run 7 to 14 days, after which the dynamic codes stop forwarding unless you pay. A code printed on a thousand flyers during a free trial can quietly die the week the trial ends — and the flyers, of course, cannot be unprinted. That is the single most common way a QR code "expires", and it is not the code expiring at all: it is a subscription ending.

Scan limits. Free plans often cap how many scans a dynamic code may receive in a month. When the cap is reached, the provider pauses the redirect — the code stops working until the month resets or you upgrade. A pause looks exactly like an expiry to the person scanning, and it strikes at the worst moment: the week your campaign finally takes off.

The provider closes. A dynamic code lives or dies with its provider. If the company shuts down, is bought, or simply stops maintaining the redirect service, every code it ever issued goes dead at once — menus, packaging, signage, business cards, all of it, with no fix except reprinting. A static code has no provider to close, which is why anything printed in volume should be static unless you genuinely need the dynamic features.

The destination disappears. This one catches static codes too. A static code pointing at a page works for as long as that page exists — delete the page, move it without a redirect, let the domain lapse, and the code scans perfectly to a dead end. The code did not expire; the address it holds stopped existing. Non-link data never has this problem: a Wi-Fi code, a contact card or a block of plain text has nothing online to disappear, so it works forever.

How to tell which kind you have

Before you print anything, scan the code yourself and look at what it actually contains — most phones show the address before opening it. If the text is your own address (your website, your menu page), the code is static and will last as long as your site does. If it is a short link on a domain you do not own, the code is dynamic and lives or dies with that account. The test takes ten seconds and it is the test that saves a print run: do it before you print, not after.

Two more checks belong in the same minute. First, scan from the distance and lighting your customers will actually use — a code that only scans at arm's length in bright light will fail on a shop window at dusk. Second, check the destination on a phone, not just a desktop: the page the code lands on must work on the device doing the scanning. Our guide to creating a QR code and testing it before printing walks through error correction, print size and contrast — the three physical reasons a code that "should" work does not.

Which kind should you make?

The rule of thumb is simple: if you will never change the destination and you do not need scan statistics, a static code is enough — and it is the only kind that is genuinely permanent. Menus, business cards, product packaging, shop windows, posters, Wi-Fi passwords, contact cards: all of these are static jobs, and paying for a dynamic code to do them is paying for features you will not use. Make the code with the QR Code Generator, download the PNG at the largest size, and print it knowing the pattern itself can never be switched off.

Dynamic codes earn their keep in exactly two situations: campaigns where the destination genuinely needs to change after printing — a seasonal offer, a ticket link that moves, a menu that updates weekly — and campaigns where you need to know how the code performs, because only a server in the middle can count scans. If either applies, go dynamic with your eyes open: pay for the plan from the start, note the renewal date next to the print order, and keep a record of which printed pieces carry which code, so a lapsed plan is a fixable afternoon rather than a silent failure across every flyer you own.

Making a code that lasts

Five habits, in order. One: use a static code unless you need editability or statistics — the QR Code Generator makes static codes with no account and no expiry. Two: point it at an address you control and intend to keep — your own domain, not a shortener you do not own. Three: print it big and dark on light, with quiet space around it, and test the printed copy before the full run. Four: if you must go dynamic, pay from day one and diary the renewal. Five: re-scan your live codes once a year — a code on a menu board can sit broken for months before anyone tells you, and a thirty-second check is the cheapest insurance a printed code has.

The pattern itself will outlast the paper it is printed on. What decides whether your code still works in five years is not the squares — it is the choice you made about what sits behind them.
