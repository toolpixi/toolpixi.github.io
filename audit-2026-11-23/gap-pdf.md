# ToolPixi PDF Gap Analysis — high-demand tools MISSING from the catalogue (2026-11-23)
Scope: the ~20 iLovePDF/Smallpdf-set tools ToolPixi does NOT have (verified against ~/workspace/toolpixi/ catalogue + batch1.md — existing PDF tools are only: merge, split, compress, pdf-to-word, pdf-to-jpg/png/webp/text, jpg-to-pdf, rotate, sign, add-page-numbers, add-text, add-watermark).
Method: worldwide monthly volume where a worldwide figure is published (kwstrends, 12-mo averages); otherwise US volume from seodata.dev (Google Ads API 12-mo averages) with the keyword cluster noted — for conversion keywords the audit consistently found US ≈ 1–8% of worldwide, so US-only rows are floors, not totals.
Hard rule applied: a tool only counts as "buildable" if the output is genuinely good in-browser. Anything whose honest in-browser quality is poor is marked NOT feasible — no fake tools.

## Ranked shortlist — genuinely feasible, by demand
1. **crop-pdf — 370K/mo worldwide, GENUINELY full-quality, SMALL build, low SEO difficulty (KD 18). Best first build in the whole gap list.**
2. **unlock-pdf — ~40K/mo US cluster, GENUINELY full-quality via qpdf-wasm, small–medium build.** (Privacy story is strongest here: password + file never leave the device — server competitors literally ask for both.)
3. **protect-pdf — ~12K/mo US cluster, GENUINELY full-quality via the same qpdf-wasm integration** (build unlock + protect + repair as one qpdf bundle: three tools, one engine integration).
4. **ocr-pdf — ~25K/mo US cluster (worldwide higher), genuinely feasible via tesseract.js; slower than server but real, and it also unlocks scanned-PDF support for pdf-to-excel/pdf-to-text later.**
5. **organize-pdf — ~20K/mo US cluster, GENUINELY full-quality, small–medium; natural extension of existing merge/split code.**
6. **compare-pdf — ~15K/mo US cluster, genuinely feasible text diff, medium build.**

## Big-demand but caveat-class (build only with honest on-page expectations)
- **pdf-to-excel — 2.1M/mo worldwide** (biggest number in the gap; output genuinely good on clean digital tables, weak on scans/complex tables) — medium build, SheetJS + pdf.js.
- **edit-pdf — largest US cluster (edit pdf 90.5K + pdf editor 246K)** — overlay editor only; large build; never promise Acrobat-style text reflow.
- **word-to-pdf — 110K/mo US + variants** — mammoth.js route; simple docs fine, complex docs degrade; the widest quality gap of the high-volume set.
- **html-to-pdf — 280K/mo worldwide** — small build, raster-output caveat.
- **excel-to-pdf (~35K US cluster), pdf-to-powerpoint (~65K US cluster), powerpoint-to-pdf (~85K US cluster)** — all caveat-class Office conversions; PPT-to-PDF is the weakest and the largest build.

## Do NOT build (honest verdict: cannot be done properly in-browser)
- **translate-pdf** (110K/mo worldwide — real demand, but needs a server-class MT engine)
- **ai-pdf-summarizer** (~22K/mo US cluster — needs a server LLM, or a weak toy model)
- **pdf-to-pdfa** (output would fail the very validation it claims to pass)
- **redact-pdf** — buildable ONLY via the secure rasterise route with honest labelling; the standard black-box-overlay version must never ship.
