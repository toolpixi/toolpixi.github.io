## Defects

### D-1 — Minor — compress-jpg-to-100kb, compress-png-to-100kb: output larger than input, reported as success
Evidence: a 1.7 KB sample image produced "Original size 1.7 KB / Compressed size 3.5 KB /
You saved 0% smaller / Done — your image is at or under 100 KB".
Suspected cause: the tool re-encodes at a fixed quality and never compares against the
original; there is no "keep the original when it is already smaller" guard, and the result
copy does not flag that the file grew.

### D-2 — Minor — mp4-to-mp3, video-compressor, compress-video-for-discord: silent death if the CDN is unreachable
Evidence: with cdn.jsdelivr.net unreachable, the tools' module script never executes —
the dropzone does nothing and the Convert button stays disabled forever, with no error
message to the user (verified by blocking the CDN in-browser). When the CDN files were
served by interception, all three tools worked end-to-end (sample.mp3 /
sample-compressed.mp4 downloads produced).
Suspected cause: ffmpeg-tools.js loads @ffmpeg/ffmpeg + core from jsDelivr via top-level
ESM imports; an import failure kills the whole module, and loadFFmpeg()'s catch only
resets the promise — nothing surfaces an error in the UI. Architectural note: these are
the only tools on the site that depend on a third-party CDN at runtime; everything else
is self-hosted.

### D-3 — Minor (observation, not reproduced) — age-on-date stray validation note
Evidence: during the first-pass automated run, the panel showed a computed result AND the
note "Please pick the date to calculate the age on." A clean retest with both dates set
showed the correct result with no stray note. Flagged for a look during the fix pass;
could not be reproduced on demand.
