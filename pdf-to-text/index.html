How to use it

Why extract text from a PDF?

Extracting a PDF's text turns a fixed-layout document into plain words you can work with: lift a quote for an article, grab passages for citations, reuse your own content in a new document, or feed a report into translation and summarising tools without retyping it by hand.

This works on text-based PDFs — documents created from Word, Google Docs, a browser's “print to PDF”, or exported from an app. It does not work on scanned PDFs (photos of pages). A scanned page contains no text to extract, only pixels; reading it requires OCR (optical character recognition), which this tool does not do. If your extraction comes back empty, your PDF is almost certainly a scan.

Getting the words out of the document

PDF is where text goes to be looked at, not used. The words in a PDF are locked in a fixed layout — hard to search across documents, awkward to quote, impossible to feed into a spreadsheet, a translation tool or a text editor. Extracting the text sets it free: the document's content becomes a plain-text file you can search, copy, count, analyse, paste into other tools or hand to an AI assistant as context. Contracts get summarised, reports get quoted, long documents get searched for the one clause that matters.

Understanding what extraction can and cannot do saves real frustration. It reads the PDF's text layer — the actual character data the file carries — and it reads it well: multi-page documents, reports, ebooks and exported files yield clean, ordered text. But a scanned document has no text layer at all; it is a photograph of a page wearing a PDF coat. Extraction from a scan returns nothing, or next to nothing, because the words exist only as pixels. That job needs OCR — a different technology that reads the picture — and no honest extractor pretends otherwise.

Layout is the other expectation to set: plain text keeps the words and their reading order, not the columns, tables and typography. What you get is the content, ready to work with — which for searching, quoting and analysing is exactly the point. Extraction runs in your browser on your device; the document is never uploaded, so the contract or statement you are mining for its own words stays private.

Questions, answered

Does it work on scanned PDFs?

No. Scanned PDFs are images of pages with no embedded text layer, so there is nothing to extract. Reading them needs OCR software, which this tool does not offer. PDFs created from Word, Google Docs, or “print to PDF” work fine.

Is my PDF uploaded anywhere?

No. The whole extraction happens in your browser using JavaScript. Your file never leaves your device.

Will formatting or tables survive?

No — the output is plain text only. Paragraphs, headings, bold text and table layouts are not preserved; tables and multi-column layouts come out as approximate text flow.

Is there a page limit?

Yes: 200 pages per run. Very large documents can make a browser tab slow or unresponsive, so the run stops at 200 pages and tells you the output was truncated. For bigger files, split the PDF first and extract each part separately.
